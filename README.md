- `assets/` — stylesheet, favicon, and project-poster excerpts

## Publish with GitHub Pages

1. Create a public repository named `<your-github-username>.github.io` (replace the placeholder with your actual GitHub username).
2. Upload the **contents** of this folder to the repository root. `index.html` should be at the root, not nested inside another folder.
3. Open **Settings → Pages**.
4. Under **Build and deployment**, choose **Deploy from a branch**, select `main` and `/(root)`, then save.
5. After the publishing workflow finishes, use the site link shown in Settings → Pages. Initial publication or updates can take several minutes.

The pages use relative links and do not require a build tool or server-side code. The included `.nojekyll` file tells Pages to serve the static files directly.

## Before publishing publicly

- Review the CV PDF. The current CV source includes a phone number and a WhatsApp QR code. If you do not want those details public, replace the PDF with a public-contact version before uploading.
- Confirm the official wording of the competition recognition. The current project page identifies the East Asia regional competition but intentionally does not state a rank because the supplied CV and conversation used different rank/prize descriptions.
- Confirm that project images and data may be publicly shared. Results are described as specific to the evaluated scenario; keep assumptions and baselines clear when adding detail.
- Confirm the email address and all project descriptions are accurate before publishing.
- To update the CV, replace `files/Yi_Ma_Company_CV.pdf` with a new PDF using the same filename.
